# CI Blocks 官方积木设计图

> 第一版。统一格式：积木名 → 字段 → 模式 → 场景。

---

## 一、基础分类（🧩）

### 分支条件 `cib/if-branch`

    【分支条件】
    【事件：push / pull_request / schedule / tag / workflow_dispatch】

作用：定义 `on:` 段的触发事件。

---

### 行为条件 `cib/if-action`

    【行为条件】
    【过滤键：branches / paths / tags】
    【过滤值：______________】

作用：给事件加过滤。多个值用英文逗号分隔。

示例：过滤键 branches，过滤值 main,dev → 生成 branches: [main, dev]。

---

## 二、门禁分类（🚧）

### 时间铡刀 `cib/time-gate`

    【时间铡刀】
    【选择时间：xxxx年xx月xx日 xx时xx分xx秒】
    【选择模式：开仓冻结 / 超时封仓】

模式说明：

| 模式   | 行为          | 场景               |
|------|-------------|------------------|
| 开仓冻结 | 未到指定时间，不予提交 | 竞赛题目发布、考试开考前禁止提交 |
| 超时封仓 | 超过指定时间，拒绝提交 | 竞赛封仓、作业截止、死线门禁   |

---

### 越权控制 `cib/ownership-guard`

    【越权控制】
    【监控路径：______________】
    【允许修改者：______________】
    【操作类型：force push / 任意 push / PR 合并】
    【违规动作：拒绝合并 / 仅告警 / 记录审计】

字段说明：

- 监控路径：如 backend/**，匹配要保护的目录
- 允许修改者：GitHub 用户名列表，逗号分隔；或填 CODEOWNERS 表示走文件
- 操作类型：监控哪种操作
- 违规动作：发现越权时怎么处理

场景：萌新改前端时顺手 force push 了后端目录，CI 直接拒绝。

---

### 异地容灾 `cib/branch-protect`

    【异地容灾】
    【保护分支：main / master / release/*】
    【要求 CI 通过：是 / 否】
    【要求 review 数：__】
    【禁止操作：force push / 直接 commit / 删除分支】
    【镜像分支：______________】

字段说明：

- 保护分支：要保护的分支名或通配
- 要求 CI 通过：合并前必须 CI 绿
- 要求 review 数：至少几人 approve
- 禁止操作：勾选列表
- 镜像分支：备份到哪个分支（如 backup/main）

场景：主分支被污染，备份分支还在，可快速回滚。

## 三、构建分类（🔨）

### 自动编译 `cib/build`

    【自动编译】
    【语言/工具链：Node / Python / Java / Go / Rust / 自定义】
    【版本：______________】
    【构建命令：______________】
    【工作目录：______________】
    【使用缓存：开 / 关】
    【缓存路径：______________】

字段说明：

- 语言/工具链：选后自动填默认版本与命令
- 版本：如 17、3.11
- 构建命令：如 npm run build、./gradlew build
- 工作目录：默认仓库根，单仓多包时填子目录
- 缓存：是否启用依赖缓存

场景：本地能跑、CI 跑不起来的代码，卡在编译这一步。

---

## 四、校验分类（✅）

### 成品校验 `cib/test`

    【成品校验】
    【测试命令：______________】
    【覆盖率阈值：__%】
    【允许跳过测试：是 / 否】
    【上传报告：是 / 否】
    【报告路径：______________】
    【超时（分钟）：__】

字段说明：

- 测试命令：如 ./gradlew test、pytest
- 覆盖率阈值：低于该值拒绝合并；填 0 表示不检查
- 允许跳过测试：否 时禁止 --skip-tests 之类
- 上传报告：CI 里保留测试记录，防"口头测过"
- 报告路径：如 build/reports/tests/
- 超时：防止测试卡死

场景：萌新说"我测过了"，CI 一跑全挂。

## 五、科研分类（🔬）

### 追根溯源 `cib/provenance`

    【追根溯源】
    【数据文件：______________】
    【数据哈希：______________】
    【模型版本文件：______________】
    【复现命令：______________】
    【结果比对文件：______________】
    【不一致动作：拒绝 / 告警】

字段说明：

- 数据文件：要校验的数据路径
- 数据哈希：预期 SHA256，留空则自动计算并记录
- 模型版本文件：如 model/version.txt
- 复现命令：重跑模型的命令
- 结果比对文件：提交的结果 JSON / CSV，跑完后与实测对比
- 不一致动作：不一致时拒绝还是只告警

场景：建模手改了模型、代码手没改代码，论文数据对不上。

## 六、项目分类（📦）

### 契约对应 `cib/contract`

    【契约对应】
    【契约类型：OpenAPI / Protobuf / GraphQL / JSON Schema / TypeScript】
    【契约文件：______________】
    【前端代码目录：______________】
    【后端代码目录：______________】
    【不一致动作：拒绝 / 告警】

字段说明：

- 契约类型：选后自动选校验工具
- 契约文件：如 api/openapi.yaml
- 前端代码目录：扫描前端字段
- 后端代码目录：扫描后端字段
- 不一致动作：字段名不一致时拒绝还是告警

场景：后端返回 user_name，前端写 userName，联调时崩。

---

## 七、审计分类（📝）

### 行为记录 `cib/audit`

    【行为记录】
    【记录内容：提交 / 合并 / force push / CI 状态 / 驳回原因 / 绕过尝试】
    【输出位置：日志文件 / 数据库 / Webhook】
    【Webhook URL：______________】
    【日志路径：______________】
    【保留天数：__】

字段说明：

- 记录内容：多选，勾选要审计的事件
- 输出位置：写到哪
- Webhook URL：可选，实时推送
- 日志路径：写到仓库内哪个文件
- 保留天数：日志保留时长

场景：force push 覆盖队友代码，萌新说"不是我"，CI 有记录。
