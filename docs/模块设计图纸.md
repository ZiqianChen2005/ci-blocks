# CI Blocks 官方积木设计图

> 第二版。对齐当前实现进度，含部署分类。更新日期：2026/09/21

---

## 一、基础分类（🧩）

### 行为条件 `cib/if-action`

    【行为条件】
    【事件：push / pull_request / schedule / tag / workflow_dispatch】
    【分支】← 子积木槽
    【作业】← 子积木槽

作用：定义 `on:` 段的触发事件。

说明：是父积木，可嵌「分支条件」和作业积木。

---

### 分支条件 `cib/if-branch`

    【分支条件】
    【过滤键：branches / paths / tags】
    【过滤值：______________】

作用：给事件加过滤。多个值用英文逗号分隔。

示例：过滤键 branches，过滤值 main,dev → 生成 branches: [main, dev]。

说明：是子积木，嵌在「行为条件」的「分支」槽里。

---

### 工作流判定条件 `cib/if-workflow`

    【工作流判定条件】
    【通过时执行】← 子积木槽
    【失败时执行】← 子积木槽

作用：根据上一个业务作业的结果分支执行。

说明：
- 判定来源自动取链上前一个业务作业（门禁不算）
- 通过 / 失败两个槽内可放任意作业积木
- 不需要 finally，通过 + 失败已穷尽

## 二、门禁分类（🚧）

### 时间铡刀 `cib/time-gate`

    【时间铡刀】
    【基准时间：xxxx年xx月xx日 xx时xx分xx秒】
    【时区：UTC-12:00 ~ UTC+12:00，步长 30 分钟】
    【模式：开仓冻结 / 超时封仓】

模式说明：

| 模式 | 行为 | 场景 |
|------|------|------|
| 开仓冻结 | 未到指定时间，不予提交 | 竞赛题目发布、考试开考前禁止提交 |
| 超时封仓 | 超过指定时间，拒绝提交 | 竞赛封仓、作业截止、死线门禁 |

字段说明：

- 基准时间：用 6 个下拉框填年月日时分秒
- 时区：49 个选项，从 UTC-12:00 到 UTC+12:00，步长 30 分钟
- 模式：决定是拦"太早"还是"太晚"

实现细节：用 epoch 比较，避免字符串时区坑。

---

### 次数铡刀 `cib/count-gate`

    【次数铡刀】
    【计数来源：仓库总提交数 / 分支提交数 / 文件修改次数 / 自定义】
    【阈值：__】
    【比较：超过 / 未达 / 等于】
    【计数范围：本次 push 内 / 从仓库创建至今 / 指定时间之后】
    【模式：硬拦截 / 仅告警】

字段说明：

- 计数来源：计什么的数
- 阈值：数字
- 比较：怎么比
- 计数范围：从哪开始数
- 模式：硬拦还是只警告

场景：竞赛限制提交次数（超过 50 次拒绝）、作业要求最少提交数（少于 3 次拒绝）。

---

### 越权控制 `cib/ownership-guard`

    【越权控制】
    【负责人表：用户ID: 路径模式，多行】
    【操作类型：force push / 任意 push / PR 合并】
    【违规动作：拒绝合并 / 仅告警 / 记录审计】
    【豁免者：______________】

字段说明：

- 负责人表：每行 `用户ID: 路径模式`，如 `alice: frontend/**`
- 操作类型：监控哪种操作
- 违规动作：发现越权时怎么处理
- 豁免者：逗号分隔的用户名，如 `admin,ci-bot`

场景：萌新改前端时顺手 force push 了后端目录，CI 直接拒绝。

实现细节：用 `GITHUB_ACTOR` 和 `git diff --name-only` 匹配。

---

### 异地容灾 `cib/branch-protect`

    【异地容灾】
    【保护分支：main,master,release/*】
    【要求 CI 通过：是 / 否】
    【要求 review 数：__】
    【禁止操作：force push,直接 commit】
    【镜像分支：backup/main】

字段说明：

- 保护分支：要保护的分支名，逗号分隔，支持 `*` 通配
- 要求 CI 通过：合并前必须 CI 绿
- 要求 review 数：至少几人 approve
- 禁止操作：逗号分隔，能检测的会警告
- 镜像分支：备份到哪个分支

场景：主分支被污染，备份分支还在，可快速回滚。

注意：**真正的分支保护必须在 GitHub Settings → Branches 配置**，本积木只做检测 + 提醒 + 镜像。

## 三、构建分类（🔨）

### 自动编译 `cib/build`

    【自动编译】
    【工具链：Node / Python / Java / Go / Rust / 自定义】
    【包管理器：npm / pnpm / yarn / bun】← 仅 Node
    【版本：22】
    【安装命令：______________】← 仅自定义
    【额外 setup：______________】← 仅自定义
    【缓存：开 / 关 / 自定义】
    【缓存路径：______________】← 仅缓存=自定义
    【缓存键：______________】← 仅缓存=自定义
    【恢复键：______________】← 仅缓存=自定义
    【构建命令：build】
    【工作目录：.】

字段说明：

- 工具链：选后动态显示对应字段
- 包管理器：仅 Node 时显示
- 版本：默认 22
- 缓存：开（内置）/ 关 / 自定义
- 构建命令：Node 下可只写脚本名（如 `build`），会补 `npm run build`

各工具链的"缓存=开"行为：

| 工具链 | 缓存内容 |
|---|---|
| Node | `actions/setup-node` 的 `cache: npm/pnpm/yarn/bun` |
| Python | `actions/cache` 缓存 `~/.cache/pip` |
| Java | `actions/setup-java` 的 `cache: gradle` |
| Go | `actions/setup-go` 的 `cache: true` |
| Rust | `actions/cache` 缓存 `~/.cargo` + `target` |
| 自定义 | 不自动加 |

场景：本地能跑、CI 跑不起来的代码，卡在编译这一步。

## 四、校验分类（✅）

### 成品校验 `cib/test`

    【成品校验】
    【测试命令：______________】
    【工作目录：.】
    【超时（分钟）：10】
    【上传报告：是 / 否】
    【报告路径：build/reports/tests/】

字段说明：

- 测试命令：如 `npm test`、`./gradlew test`、`pytest`
- 上传报告：CI 里保留测试记录，防"口头测过"
- 报告路径：如 `build/reports/tests/`

场景：萌新说"我测过了"，CI 一跑全挂。

注意：**覆盖率阈值、允许跳过测试暂未实现**（因工具链差异太大）。

## 五、科研分类（🔬）

### 追根溯源 `cib/provenance`

    【追根溯源】
    【校验命令：python scripts/verify_data.py】
    【工作目录：.】
    【超时（分钟）：30】
    【上传证据：是 / 否】
    【证据路径：evidence/】
    【失败动作：拒绝 / 仅告警】

字段说明：

- 校验命令：**需要用户已有校验脚本**
- 上传证据：把结果作为 artifact 保留

场景：建模手改了模型、代码手没改代码，论文数据对不上。

说明：**空壳版**——不自动算哈希、不自动比对，用户自己写脚本。**核心价值是留证**。

## 六、项目分类（📦）

### 契约对应 `cib/contract`

    【契约对应】
    【契约类型：OpenAPI / Protobuf / GraphQL / JSON Schema / TypeScript】
    【契约文件：api/openapi.yaml】
    【校验命令：npx openapi-diff ...】
    【工作目录：.】
    【超时（分钟）：10】
    【上传差异报告：是 / 否】
    【报告路径：contract-diff/】
    【失败动作：拒绝 / 仅告警】

字段说明：

- 契约类型：选后提示对应的校验工具
- 契约文件：契约定义文件路径
- 校验命令：**用户自填**，如 `npx openapi-diff`

场景：后端返回 `user_name`，前端写 `userName`，联调时崩。

说明：**空壳版**——和追根溯源同构，用户自己写校验命令。

## 七、审计分类（📝）

### 行为记录 `cib/audit`

    【行为记录】
    【日志路径：.cib-audit/】
    【保留天数：30】
    【上传产物：是 / 否】

字段说明：

- 日志路径：日志写到哪个目录
- 保留天数：artifact 保留时长（1~90）
- 上传产物：是否上传为 artifact

记录内容：触发者、事件、分支、提交、运行 ID、上游作业结果、改动文件

场景：force push 覆盖队友代码，萌新说"不是我"，CI 有记录。

配合「工作流判定条件」：**只在上游失败时记录**。

## 八、部署分类（🚀）

### 部署到 GitHub Pages `cib/deploy-gh-pages`

    【部署到 GitHub Pages】
    【发布目录：dist】
    【目标分支：gh-pages】
    【环境：production】
    【环境 URL：______________】
    【保留历史：是 / 否】
    【CNAME：______________】

字段说明：

- 发布目录：要发布的目录
- 目标分支：发布到哪个分支
- 环境：GitHub 环境名
- 环境 URL：部署后的 URL
- 保留历史：保留 gh-pages 分支的旧文件
- CNAME：自定义域名

场景：静态站自动发布到 GitHub Pages。

前提：仓库 Settings → Pages 选 gh-pages 分支。
